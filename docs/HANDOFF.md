## TL;DR

The island is gone. The whole world is now **Naman's World Fair** — a flat, fenced 72×56 fairground you walk into through a gate. **Bo** runs the ticket booth: three lines, the **About** card, then "tickets are one word each" — the **Wordle** *is* the entry ticket, and until you win it two turnstiles physically block the gate. Inside, the résumé is the midway. The **Career Coaster** is ridden for real: the player hides, a cart follows a drawn 3-span track with a lift hill, drops, a camelback and a loop while the camera follows it, and **five content-derived milestone cards** slide in at five stops (2020 SRM · 2023 Barclays intern · 2024 SDE · the payment-lineage engine in production · the unnamed product now) before the **Career** card lands Education + Experience together. The stalls pay the rest: **claw** at the Prize Tent (one project card per prize), **Word Forge** (now persistent, with a prize board and a cumulative **tech-stack** popup), **Chalk Flight** and the **Arcade** for fun and hats, **Hook-a-Duck** at the pond (Byte the cat), and the **Guestbook** for Contact. Every game carries a visible **"show me the answers"** door — the fair is a résumé, and a résumé you have to be good at Wordle to read is not a résumé. Story spine `ticket → ride → prizes → toolkit → guestbook`; **7 quests / 23 achievements / 8 attractions**; save schema **v4**. At v4 the suite stood at **66 files / 1,105 tests / 0 skips**. Live at naman-gururani.github.io/lineage from 2026-09-03; the v5 publish on 2026-09-23 moved it to **[/portfolio/](https://naman-gururani.github.io/portfolio/)**, and old `/lineage/` links redirect there.

**v5 layers guidance on top of the same fair — nothing above changed.** Action buttons now name what they will do (RIDE, TALK, PLAY, SIGN, HOOK, TAKE, PET, PUSH, SWITCH, OPEN, READ, or SWING when nothing is in reach); a shared blink (`.nudge`) marks whatever wants a tap next and degrades to a static ring rather than vanishing under reduced motion; a new **Missions** sheet lists all eight stops with what you do, what you get, and a status; and a **"Take me there"** button routes and walks the player to any stop, cancelling on the first manual input and never crossing the turnstiles ahead of the ticket. None of it is a forced tutorial — the guided walk runs only because a player pressed the button. See "What exists — v5" below.

## What exists — v5 (guidance layer, on top of the fair above)

Nothing about the fair itself changed — no new attractions, no new content, no forced tutorial. v5 is entirely about a phone player knowing what to press and where to go, plus the `/lineage/` → `/portfolio/` code move (covered under "How to run" below).

- **Verbs on every interactable (`src/systems/verbs.ts`, pure):** `verbFor({ verb?, interact?, prompt })` picks, in order, an interactable's own declared `verb`, then a regex on its `interact` dispatch string (`booth:` → TALK, `ride:` → RIDE, `minigame:` → PLAY, `duckpond` → HOOK, `panel:zone:contact` → SIGN, `panel:` → READ), then a regex on the prompt's own wording, then `'USE'`. Live verbs at the fair: **TALK** (Bo, every NPC), **RIDE** (the coaster), **PLAY** (claw/forge/flight/crew), **SIGN** (the guestbook), **HOOK** (the duck pond), **TAKE** (a balloon), **PET** (the cat), **PUSH** (a turnstile), **SWITCH** (the lights), **OPEN** (a prize chest, `entities/Chest.ts`), **READ** (a sign or the forge board), and the idle verb **SWING** (`IDLE_VERB`, the wrench, shown when nothing is in reach). `actionLabel(prompt, verb)` builds the full sentence a screen reader hears — "Ride the Career Coaster" — by putting the verb in front of the name, except where the prompt already opens with its own verb ("Talk to Bo"), which is left alone rather than read twice. `Interactable.verb?` (`src/systems/Interact.ts`) is optional; `setCurrent` always emits a resolved verb on `ui:prompt` (`{ text, key, verb }`, widened in `src/core/events.ts`), so every consumer — the touch button, the desktop prompt chip — reads the same word without re-deriving it.
- **Touch buttons that say what they do (`src/ui/touch.ts`):** the **A** button (`.tb-a`) shows the live verb, dims and reads **SWING** when idle, and carries the verb in its `aria-label` via `actionLabel`; **B** (`.tb-b`) reads **JUMP**. Both stay pill-shaped, ≥44px (86px / 64px).
- **The nudge — one shared blink, class `.nudge` (`src/styles/ui.css`):** an expanding ring that grows out of a control and fades, ~1.15s a cycle; under `prefers-reduced-motion` or the in-game `.reduce-motion` toggle it stops animating but stays drawn at fixed opacity — the cue is never removed, only stilled. Applied at **seven** call sites (the original brief specified six; the Missions button was added at Task 6 with different timing): **(1)** the touch action button, toggled with `ui:prompt`'s idle state (`touch.ts`); **(2)** the desktop prompt chip's `.pkey`, added every render (`ui/prompt.ts`) — the chip is rebuilt each time, so there is nothing to remove; **(3)** the dialogue continue arrow, added once a line finishes typing and removed on advance/finish (`ui/dialogue.ts`) — on coarse-pointer layouts the arrow also gains `role="button"`, `tabindex="0"` and the visible/accessible name "Tap to continue", with a click handler that calls the same `act()` Enter/Space/E use and then `stopPropagation()`, because without it a tap on the arrow also fires `.dlg-box`'s own delegated click handler and skips a line; **(4)** the ride card's **Next ▶**, static in its class list from the moment the card renders (`ui/ridecard.ts`); **(5)** the welcome card's **Start**, static while the card is open (`ui/welcome.ts`); **(6)** the map's **Travel ▶**, toggled on once a discovered target is selected (`ui/map.ts`). **(7)**, the HUD's Missions button (`ui/hud.ts`), is not an availability cue like the other six — it pulses for a fixed **3 cycles (3.5s, `NUDGE_MS`)** when `story:changed` fires and drops early the moment the Missions panel opens, because the story moving on, not "you can press this right now," is what it flags.
- **The Missions sheet (`src/ui/missions.ts` + `src/styles/missions.css`, data in `src/data/missions.ts`):** `MISSIONS` is 8 entries, one per attraction (5 on the story spine — gate → coaster → prizetent → forge → guestbook — then the 3 side stalls), each with `does` (what you do), `gives` (what you get — no digits, no résumé facts, the cards hold those), and how it is marked done (zones unlocked / a quest / found). `missionStatus(m, view)` returns `done` / `next` (the single first-unfinished story stop) / `open` / `locked` (any story stop past the gate before the ticket is won). The gate's own row is `done` only once the **ticket** flag is set, not once `about` unlocks — the arrival cutscene hands `about` over before Bo's question is even asked, which otherwise ticked the gate off on a brand-new save and left nothing marked `next` at all (fixed in `ecfa19c`; the rule lives in `isDone` so every caller agrees, not just the sheet). The sheet renders a status pill, the attraction's own `Attraction.name` (never retyped), both copy lines, and a **Take me there** button per row; a row whose real destination differs from its heading (anything past the gate, pre-ticket) says so up front ("Gate first — this walks you to Bo."). Opened from a new 5th HUD button (`.hbtn-missions`, first in the row) and from the objective chip (which used to open the map). The sheet also owns a slim **guide bar** at the top of the overlay (`.ms-bar`), shown on `guide:state {to}` while the world is walking the player somewhere.
- **The guided walk ("Take me there"):** `src/systems/guide.ts` (pure) provides `guideTarget(id, ticket)` (the redirect rule — a locked destination becomes `'gate'`), `routeTiles(grid, from, to, blocked)` (wraps the world's own `astar` from `world/paths.ts`; cost 1 on paved tiles, 1.4 elsewhere, `Infinity` on a blocked one; `null` if the destination tile is out of the grid or unreachable), `waypoints(path)` (collapses a tile path to its corners) and `stepAlong(px, py, wps, i, reach = REACH_PX)` (one frame of unit-vector steering; `REACH_PX = 10`). `WorldScene` (`src/scenes/WorldScene.ts`, ~300 new lines) owns the runner: `startGuide(id)` re-applies `guideTarget` regardless of what arrives on `world:guide` (so the sheet and the world can never disagree), builds a blocked-tile lookup from the scene's own collision data in two passes (`this.solids` first, then `this.hardSolids` on retry — the turnstiles, the perimeter and every booth stand in both, so a shut gate is never crossed by either pass), and on a route draws a bobbing arrow over the door (`guide_arrow`, a new 18×20px atlas sprite in `src/art/sprites/props.ts`) plus up to 24 fading trail dots (`GUIDE_DOTS`) that burn down behind the player as they pass. Each frame the movement block feeds `stepAlong`'s unit vector into the same `player.move(...)` the joystick drives, so collision, footsteps, animation and region banners are untouched; **any manual input** (stick, key, pad) past a magnitude of 0.15 cancels the walk on that same frame. No forward progress for **1500ms** (`GUIDE_STUCK_MS`) re-routes once; a second stall falls back — but `guideFallback` checks the ticket flag *again* before ever calling the pre-existing `travelTo`, because a `null` route before the ticket almost always means "the park is shut" (the two turnstile halves cover the entire gate opening while they stand), not "this player is stuck," and fade-travelling a ticketless player past them would skip the one puzzle the fair is built around. On arrival the player faces the door and the ordinary interact update raises the prompt on the same frame — which is what starts the action button blinking with the destination's verb.
- **One onboarding hint, touch only, once per save:** after Bo's arrival greeting closes, a touch player — not a keyboard one; that legend is now gated `!touchLayout()` so it never fires on a phone at all — gets one deferred toast, `"Lost? Tap Missions — it can walk you there."`, via `GameState.guideHintOnce(touch)`, gated on the `guide_hint` save flag. It waits **4.5s** (`this.time.delayedCall(4500, …)`) because the same instant already carries the arrival badge, its XP, the gate's discovery toast and the banner — firing immediately would spend most of the hint's visible time buried under them. The welcome card's touch legend (`HOWTO_TOUCH`) was rewritten to match what actually exists: drag the stick / JUMP / "the big button — it names what it will do" / "Lost? Missions walks you there."
- **The HUD at narrow widths (`src/styles/ui.css`):** below **720px** the HUD wraps to two rows (`flex-wrap` on `.hud`) instead of letting the tools card and the identity cluster overlap — the tools card (`.hud-right`, `order: -1`) takes the top row, the cluster (`.hud-left`) the next. Between **721–1000px** the two cards still share one row, and the cluster reserves **470px** (measured against the 5-button tools card at 462px; a stale 370px reserve, predating the Missions button, used to let the two card backgrounds overlap by ~55px around 800px wide). Below **640px** every tool button drops its label except Missions, which keeps its word — it is the one button the welcome card and the hint both tell a lost player to tap by name. `.hud-right { order: -1 }` reorders the row **visually only**; it does not change tab order at ≤720px (a known, non-blocking cosmetic note — backlog). The interact prompt (`.prompt`) lifts clear of the touch button row via a `#ui.touch-on` class on the overlay root (`initPrompt` runs before `initTouch`, so no `~` sibling rule could reach backwards), and lifts again, further, when the minimap is also showing (`:has(.minimap:not(.hidden))` — this codebase's first use of `:has()`; it degrades safely, losing only the extra minimap-avoidance offset in an unsupporting browser).

## Conventions & critical gotchas

1. **Never commit/push/deploy unless the user asks.** Everything is committed and pushed (`main` = `origin/main`); gh-pages is published by `npx gh-pages -d dist`. Commit trailers: a `Co-Authored-By:` line naming the model that actually wrote the commit — it varies by session and by subagent, and history already holds Fable 5.1, Sonnet 5 and Opus lines — plus `Claude-Session: <url>`.
2. **Content rules:** facts about Naman only from `src/data/resume.ts` (the v6 master record, which the résumé page renders and `content.ts` reads its shared facts from) and `src/data/content.ts`; dialogue carries **no digits** and no facts (cards do); skills = approved set only. Since v6 the product is named, **Enlacey**, live on Google Play (the claw box stays `???` as a game mechanic). Public pages never mention applications, tests or target schools, and bank detail stays at orders of magnitude with no internal names (`tests/helpers/banned.ts`). Wordle answers, Forge words **and every coaster stop string** are derived from / drift-tested against content. `index.html`'s description + noscript block are pinned to content too (`tests/index-html.test.ts`).
3. **Keyboard:** world input via `src/core/keys.ts` only; `ui/*` never imports it (module-graph test). Mini-game renderers attach their own listeners to the modal root with `e.repeat` guards.
4. **Footprint drawing (v4):** `WorldScene.drawFootprint()` draws **both** structures and attractions — origin `(0.5, 1)`, i.e. centred on the footprint standing on its bottom edge, depth = that bottom-edge y. `buildStructures()` runs **before** `buildAttractions()`, and they share the same depth scheme, so overlap is resolved by y alone (the station sits flush at the spans' foot on purpose). A sprite taller or wider than its plot overhangs — that is deliberate for the coaster, the wheel and the pond stall.
5. **Solids come from three helpers, not from the art:** `boundarySolids(bp)` = the hard full-tile perimeter ring (the decorative fence/bush props are separate and stay **low**, so hopping still works over decor but never over the boundary); `structureSolids(bp, flags)` = the structures, gated ones only while their flag is unset; `attractionSolids(a)` = the footprint, or `solidCols` for the gate arch's two pillars. Never infer a solid from a sprite's rectangle.
6. **The interact radius is small — 26 px** on attraction doors (28 on the forge board, which was widened for exactly this reason). A walk that drifts a tile off the door gets no prompt. When scripting a browser walk, aim at the **door tile centre**, and check `window.__game.scene.getScene('world').interact.current` to see what is actually in range before pressing the key. Doors sit at `priority: 4`, one rung above NPC talk (3): on a door tile the door wins even with a keeper standing on the step (Ilse used to swallow the guestbook's E); a step to the side and you talk to them.
7. **Night overlays** are `${sprite}_night` images at `NIGHT_GLOW_DEPTH = 91000` — **above** `DayNight`'s veil (depth 90000) and deliberately **outside** `tintables`, or the lit coaster gets graded down by the very darkness it exists to break.
8. **Known latent trap (backlog, not a v4 regression):** NPC, player and companion sprites are pushed into `tintables` from `buildNpcs()`, which runs *after* `registerTinted` has already spread its argument — so those registrations never reach `DayNight`. They are untinted at night, which is accidentally why the coaster cart looks right. Fixing the registration would make the cart the one untinted thing on screen; fix both or neither.
9. **Purity:** `core/`, `world/`, `src/games/*`, `src/data/*` and `systems/ridepath.ts` never import Phaser or DOM (exception: `core/events.ts`). Games are pure reducers; renderers are thin DOM/canvas; simulation is driven only by `createLoop`, never timers.
10. **Minigame framework:** rewards/records happen ONLY in `MinigameHost.teardown()`; chapters unlock through `GameState.unlockFacet(zoneId, announce)` — the claw calls it with `announce=false` *before* opening the card itself; the panel layer's `facet:unlocked` listener pushes into `uiState.unlocked` **before** deciding whether to queue a card. Renderers that can outlive their win expose `won()`. `host.progress(data)` → `GameState.minigameProgress(id, data)` is the persistence seam; `WorldScene.openPanel()` is the **only** place that attaches the forge payload, so every route to the board is fed.
11. **Story wiring:** Bo's `intro` node is not in his entry ladder — only the fresh-save arrival runs it, and it unlocks `about` before the card effect flushes. `uiState.unlocked` is a **copy** of the save array. Bo relocates between `storySpots` only **off-camera**. `objectiveFor()` returns `null` once `story_done` is set, whatever the step says — that is what hides the HUD chip and the map marker after the finale.
12. **Art pipeline:** 32 px/tile; palette keys only; new packs register in `src/art/atlas.ts` (`allDefs()` now spreads FAIR_DEFS and RIDE_DEFS, and `tests/atlas-capacity.test.ts` pins that list); per-pack tests pin dims/anchors; render `npm run preview:art -- sheet <pack> 3` and look. Style rules: `.superpowers/sdd/2026-09-01-naman-world-hd/art-direction.md`.
13. **Browser testing protocol:** the dev server on `:5173` hot-reloads on every source change — with agents editing concurrently, **build and test against `npx vite preview --port 4173` instead**. URL flags: `?fresh=1`, `?cheat=1` (Skip in every game), `?word=<answer>`, `?duck=gold`, `?st=1` (timer stepping; distorts feel). Synthetic window `KeyboardEvent`s reach `core/keys` consumers but **not** element-scoped listeners — use real CDP keys/clicks, and **hold the world's action key ~120 ms**; a shorter tap is routinely missed. A gag modal intercepts pointer clicks (use `document.querySelector(...).click()` from `browser_evaluate`). `window.__game` / `window.__events` are exposed; `__game.scene.getScene('world')` gives `.state` (live GameState) and `.interact`; `__events.emit('ui:panel', {id:'minigame', data:'<id>'})` opens a game directly.
14. **Windows shell:** long heredocs get mangled — write `scratch/*.cjs` with the Write tool. **Playwright MCP's browser profile is shared across sessions** and refuses a second user ("Browser is already in use"); when that happens, drive `playwright-core` from the MCP's npx cache directly (`C:/Users/Naman/AppData/Local/npm-cache/_npx/<hash>/node_modules/playwright-core`, `chromium.launch({ channel: 'chrome', headless: true })`) — `scratch/recheck*.cjs` are working examples (fresh save → Bo → ticket → ride → games → finale, with `window.__game` probes).
15. **Registry invariant:** every zone is delivered by exactly one attraction, the 8 attraction ids are the discoverable set, and `DISCOVERIES_FOR_100` is 8 (`tests/registry.test.ts`).
16. **Parallel agents:** disjoint file ownership per task, one CSS file per game (`src/styles/games/<id>.css`), review packages were built from working-tree snapshots (`scratch/snap.sh`, `scratch/pkg.sh`) while the work was uncommitted; from here on plain `git diff <base>` does the same job.

**v5 additions:**

17. **The verb has one source and reaches the UI through one field.** Every interactable's action word comes from `src/systems/verbs.ts`'s `verbFor()` — do not hand-write a verb string anywhere but an interactable's own `verb?` field. It reaches the DOM exactly one way: `Interact.setCurrent()` resolves it once and puts it on `ui:prompt {text,key,verb}`; the touch button and the desktop prompt chip both only read that field, never re-derive it. A new call site that sets `prompt` without `verb` still works, since `verbFor`'s dispatch-string and prompt-wording fallbacks catch it — but check `tests/verbs.test.ts` before trusting a new fallback silently.
18. **The nudge degrades, it never disappears — and it has a specificity trap.** `.nudge` (`src/styles/ui.css`) is `position: relative` plus an absolutely-positioned `::after` ring; under `prefers-reduced-motion` or `.reduce-motion` the ring stops animating but stays drawn at fixed opacity, because the cue itself, not the motion, is the point — deleting the class under reduced motion instead of freezing it would silently break the spec. This already broke once and was fixed in `8d89898`: any element that needs its own `position: absolute` (like `.dlg-next`) collides with `.nudge`'s `position: relative` at equal specificity, and which one wins depends on stylesheet import order in `main.ts` — invisible until somebody reorders an import. The fix pattern is a colocated two-class override (`.dlg-next.nudge { position: absolute }`) next to the element's own rule, not stripping `position` from the shared `.nudge` block. Check any *new* nudge target for the same collision before adding it.
19. **A ticketless player cannot be walked or faded past the turnstiles — enforced in three places, not one.** `guideTarget(id, ticket)` (`src/systems/guide.ts`) redirects any locked destination to `'gate'`, and both the Missions sheet and `WorldScene.startGuide()` call it independently rather than trusting whatever arrives on the `world:guide` event, so the two cannot disagree. `WorldScene.guideRoute()` builds its blocked-tile map from `this.solids`, and, on the fallback pass, `this.hardSolids` — the turnstile halves and the boundary ring sit in both, so neither pass can route through a shut gate. And `guideFallback()`, reached only when a route is `null`, re-checks the ticket flag itself before ever calling the pre-existing `travelTo()`, because a `null` route pre-ticket means "the park is shut" (the two turnstile halves cover the entire gate opening while they stand), not "this player is stuck" — and `travelTo` fade-travelling them in would skip the one puzzle the whole fair is built around. Touch any one of the three without checking the other two and a route to a locked stop becomes possible again.
20. **The HUD's two width breakpoints are disjoint rules that both have to keep working.** Below **720px** (`@media (max-width: 720px)`) the HUD wraps to two rows — `.hud { flex-wrap: wrap }`, the tools card (`.hud-right`) forced to `order: -1` so it renders first, the identity cluster (`.hud-left`) taking the row under it. Between **721–1000px** the two cards still share one row and `.hud-cluster` instead reserves `calc(100vw - 1.4rem - 470px)` so it stops short of the tools card rather than sliding under it — 470px is the *measured* width of the 5-button tools card (462px) plus the HUD's own padding; it used to say 370px (right before the Missions button existed) and the stale number let the two card backgrounds overlap by ~55px around 800px wide. These are two different layout strategies for two different width bands, not one rule with a threshold — touching one without checking the other reintroduces the overlap the v5 fix wave closed. (Known cosmetic-only leftover: `.hud-right { order: -1 }` changes the visual row order at ≤720px but not the tab order — backlog.)
21. **"Guide" names two unrelated things in `WorldScene.ts` — do not conflate them.** `BO_WALK_SPEED` / `BO_ARRIVAL_SPEED` and the nearby NPC-roster comments are about **Bo**, the ticket-booth host, walking on screen during the arrival cutscene. The **player**-facing "Take me there" system lives in the `/* ---------------- take me there ---------------- */` block much further down the same file (`this.guide`, `startGuide`, `guideRoute`, …) and in `src/systems/guide.ts`. They share a name by coincidence of English, not by any shared code — searching the file for "guide" hits both.
22. **v5's browser verification is emulation-only, and its scripts live in gitignored `scratch/`.** Three drive the v5 behaviour and can be re-run against the static preview on :4173: `scratch/recheck-guide.cjs` (the guided walk at 390×844 touch — a ticketless walk redirected to the gate, a ticket-won walk to the coaster that arrives on RIDE with the nudge, a stick push cancelling it); `scratch/demo/walkthrough.cjs` (a scripted playthrough — Bo's Wordle ticket, Missions, a guided walk, every coaster card, the claw — recorded as video; `--local` targets the previews, no flag targets the live site); and `scratch/demo/livecheck.cjs` (the live `/portfolio/` boot, the `/lineage/` redirect keeping its query and hash, and the homepage's play button). Screenshots from the v5 checks are `scratch/shots/v5-*.png` and `v5fix-*.png`. **Environment and tooling, learned in the v5 publish session:**

23. **A subagent's report can arrive before its work lands.** Twice in v5 a subagent's hand-back carried a commit hash that did not exist yet, followed later by a second report with the real one. Once that was misread as fabrication and the task was re-dispatched, which put two agents on the same files until the overlap was caught. Before acting on any report, resolve its hash with `git cat-file -t <hash>`; before re-dispatching, check whether the first agent is still running; and never conclude fabrication from a late or garbled message.
24. **Git Bash rewrites any argument that starts with `/`.** Handing an API path such as `/repos/Naman-Gururani/portfolio` to a script from Git Bash turns it into a Windows path (`C:/Program Files/Git/repos/…`), which shows up as a nonsense host like `api.github.comc`. Prefix the command with `MSYS_NO_PATHCONV=1`, or run it from PowerShell.
25. **Calling the GitHub API from this machine.** `gh` is not installed, and the GitHub MCP server fails to connect ("Authorization header is badly formatted"). Git's stored credential works instead: `printf 'protocol=https\nhost=github.com\n\n' | git credential fill` prints `password=<token>`, a token with admin rights on all three repos and the `workflow` scope (it renamed this repo and pushed the profile's workflow files). Use it **in-process only** — never echo it, write it to a file, or put it on a command line that gets logged. The publish used a ~50-line Node helper that read it with `execFileSync('git', ['credential', 'fill'])` and called `fetch`; that helper lived in a temporary scratchpad and is gone, so rewrite it if you need it.
26. **Files sent to the owner's device are capped at 30 MB.** The full-quality laptop walkthrough is 78 MB; its share copy was made with a two-pass H.264 encode at 1100 kbit/s (`-preset slow -tune animation`), which keeps the pixel art crisp at about 27 MB.
